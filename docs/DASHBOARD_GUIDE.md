# Power BI dashboard: build guide

There are two ways to get the dashboard:

- **Option A: open the generated project** (`powerbi/AutoVoice.pbip`, about 10 minutes). The data model,
  relationships, all DAX measures and the 3 report pages are already defined as text files.
- **Option B: build it by hand** (sections 1 to 7 below, 3 to 5 hours). Recommended at least once,
  even if you use Option A: interviewers ask how the model and measures were built, and doing it
  yourself is the best way to be able to answer.

## Option A: open the generated Power BI project

`powerbi/` is a **Power BI Project (PBIP)**: the same content as a `.pbix`, saved as readable text so it
works with git. It is produced by `python powerbi/build_pbip.py`.

| Part | Format | What is inside |
|---|---|---|
| `AutoVoice.SemanticModel/` | TMDL | 9 tables loaded from CSV, 3 relationships, 19 DAX measures, a `DataFolder` parameter |
| `AutoVoice.Report/` | PBIR | 3 pages, 28 visuals, AutoVoice colour theme |
| `AutoVoice.pbip` | JSON | The file you double-click |

**How it was checked (Power BI itself cannot run on Linux):** the data model was loaded and re-saved with
Microsoft's Analysis Services library (the same TMDL reader Power BI uses), and every report file was validated
against Microsoft's published JSON schemas. What could **not** be tested is the first open and refresh in
Power BI Desktop. If something fails, see *Troubleshooting* below.

### Steps

1. **Install Power BI Desktop** (free) from the Microsoft Store, or update it to the latest version.
2. **Get the files onto your PC:** on GitHub, *Code → Download ZIP*, or `git clone` the repository.
3. **Put the data where the model looks for it.** The model reads CSVs from `C:\AutoVoice\powerbi_data\`.
   Either copy the repo's `powerbi_data` folder there, or keep it where it is and change the path in step 5.
4. **Open `powerbi/AutoVoice.pbip`** (double-click, or *File → Open* in Power BI Desktop).
5. **If your data is somewhere else:** *Home → Transform data → Edit parameters → DataFolder*, paste the
   folder path **ending with a backslash** (for example `D:\Projects\Data-analyst\powerbi_data\`),
   then *Apply changes*.
6. **Home → Refresh.** Wait for all 9 tables to load (about 11,500 reviews).
7. Click through the 3 pages, then **File → Save** (it saves back into the PBIP folder).
   *File → Save as → .pbix* if you also want a single-file copy.

**What you should see:** Overview KPI cards showing 11,496 reviews, an average rating of 3.64 and 14.9% rated 1-2 stars.
On page 2 the left bar chart ranks price first and the right one ranks service first. On page 3, the
Velora line crosses the alert limit at 2022Q4.

### Troubleshooting

| Problem | Fix |
|---|---|
| "This file format isn't supported" / PBIP won't open | Update Power BI Desktop. On older versions, turn on *File → Options → Preview features →* **Power BI Project (.pbip) save option**, **Store semantic model using TMDL format** and **Store reports using enhanced metadata format (PBIR)**, then restart |
| Refresh error *"Could not find a part of the path"* | The `DataFolder` parameter is wrong (step 5). The path must end with `\` |
| Error about the theme `AutoVoiceTheme.json` | Open `AutoVoice.Report/definition/report.json`, delete the `customTheme` block and the `resourcePackages` entry, save, reopen. Then apply a theme from *View → Themes* |
| One visual shows an error or is empty | Select it and re-drag the fields listed in sections 3 to 5 into its wells. Send me the error text and I'll fix the generator |
| Numbers look 100× too big or decimals are wrong | The model parses CSVs with `en-US` number format on purpose; check that the CSVs weren't opened and re-saved in Excel |

To change anything permanently (titles, measures, layout), edit `powerbi/build_pbip.py` and run it again.
Edits made inside Power BI Desktop are saved to the PBIP folder too, but are overwritten if the generator runs again.

# Option B: build it by hand

## 0. Files you need

All in `powerbi_data/` (generated by `python run_pipeline.py`):

| File | Rows | Role |
|---|---:|---|
| `fact_reviews.csv` | 11,496 | **Fact table**: one row per review |
| `bridge_review_theme.csv` | 16,362 | One row per (review, theme) with theme sentiment |
| `dim_brand_model.csv` | 18 | Brand and model |
| `dim_date.csv` | ~2,200 | Calendar |
| `theme_priority.csv` | 6 | Pre-computed driver analysis (stars lost per complaint) |
| `brand_ranking.csv` | 8 | Raw and sample-size-adjusted brand ratings with CIs |
| `alerts.csv`, `control_chart.csv` | | Early-warning results |
| `scenarios.csv` | 6 | What-if table |

## 1. Load and model the data

1. **Home → Get Data → Text/CSV**, load each file. In Power Query, check types:
   `date` columns = Date, `rating` = Whole number, `theme_sentiment` = Decimal.
2. **Model view**, create relationships (all single direction, many-to-one):

```
dim_brand_model[model_key]  1 ──< *  fact_reviews[model_key]
dim_date[date]              1 ──< *  fact_reviews[date]
fact_reviews[review_id]     1 ──< *  bridge_review_theme[review_id]
```

3. On the `fact_reviews → bridge_review_theme` relationship set **Cross filter direction = Both**.
   This lets a *theme* slicer filter reviews.
   *(Interview point: bidirectional filters can cause ambiguity in larger models; here there is only
   one bridge table, so it is safe.)*
4. Mark `dim_date` as a date table: **Table tools → Mark as date table → date**.
5. Leave `theme_priority`, `brand_ranking`, `alerts`, `scenarios` **unrelated**. They are pre-aggregated
   summary tables used on their own visuals.

## 2. DAX measures

Create a blank table called `_Measures` (**Home → Enter data → OK**) and add these measures to it.
(In the generated PBIP, the review measures live on `fact_reviews` in display folders such as *KPIs*,
*Trend* and *Themes*; the theme-priority and Velora early-warning measures live on their own tables.
The generated `Avg Rating YoY` compares the latest year in the selection with the year before, so the
card makes sense even with no year selected.)

```DAX
Total Reviews = COUNTROWS ( fact_reviews )

Avg Rating = AVERAGE ( fact_reviews[rating] )

% Negative =
DIVIDE (
    CALCULATE ( [Total Reviews], fact_reviews[rating] <= 2 ),
    [Total Reviews]
)

% Positive =
DIVIDE (
    CALCULATE ( [Total Reviews], fact_reviews[rating] >= 4 ),
    [Total Reviews]
)

-- Reviews mentioning the theme(s) currently in filter context
Theme Mentions = DISTINCTCOUNT ( bridge_review_theme[review_id] )

Negative Theme Mentions =
CALCULATE (
    DISTINCTCOUNT ( bridge_review_theme[review_id] ),
    bridge_review_theme[theme_polarity] = "negative"
)

% Mentions Negative = DIVIDE ( [Negative Theme Mentions], [Theme Mentions] )

-- Share of ALL reviews (ignoring the theme filter) that complain about the theme
Complaint Rate =
DIVIDE (
    [Negative Theme Mentions],
    CALCULATE ( [Total Reviews], REMOVEFILTERS ( bridge_review_theme ) )
)

-- Average rating of reviews that complain about the selected theme
Avg Rating When Complained =
CALCULATE (
    [Avg Rating],
    bridge_review_theme[theme_polarity] = "negative"
)

-- Year-over-year change in average rating
Avg Rating PY =
CALCULATE ( [Avg Rating], SAMEPERIODLASTYEAR ( dim_date[date] ) )

Avg Rating YoY = [Avg Rating] - [Avg Rating PY]

-- Rolling 3-month average rating (smooths noisy months)
Avg Rating 3M Rolling =
CALCULATE (
    [Avg Rating],
    DATESINPERIOD ( dim_date[date], MAX ( dim_date[date] ), -3, MONTH )
)

-- Fair comparison for small brands: shrink toward the overall mean
-- k = 21 comes from src/drivers.py (prior strength, in reviews)
Adjusted Rating =
VAR k = 21
VAR n = [Total Reviews]
VAR overall = CALCULATE ( [Avg Rating], REMOVEFILTERS ( dim_brand_model ) )
RETURN DIVIDE ( n * [Avg Rating] + k * overall, n + k )

-- KPI card subtitle, e.g. "vs 3.64 market"
Market Avg Label =
"vs " & FORMAT ( CALCULATE ( [Avg Rating], REMOVEFILTERS ( dim_brand_model ) ), "0.00" ) & " market"

-- Impact-weighted priority, from the pre-computed regression table
Stars Lost per 100 Reviews = SUM ( theme_priority[stars_lost_per_100_reviews] )
```

**Formatting:** `% Negative`, `% Positive`, `% Mentions Negative`, `Complaint Rate` → Percentage, 1 decimal.
`Avg Rating`, `Adjusted Rating` → Decimal, 2 places.

## 3. Page 1: Overview

**Purpose:** "How are we doing, and who is behind?"

| Visual | Settings |
|---|---|
| 4 KPI cards (top row) | `Total Reviews`, `Avg Rating` (subtitle: `Market Avg Label`), `% Negative`, `Avg Rating YoY` |
| Line chart | X = `dim_date[month_start]`, Y = `Avg Rating 3M Rolling`. Add a constant line at the overall average |
| Bar chart (horizontal) | Y = `dim_brand_model[brand]`, X = `Adjusted Rating`, sorted ascending. Tooltip: `Total Reviews` |
| 100% stacked bar | Y = brand, X = `% Negative`, `% Positive` |
| Slicers (one row at the top) | `dim_date[year]` (between), `fact_reviews[dealer_region]`, `fact_reviews[verified_purchase]` |

## 4. Page 2: Complaint Themes

**Purpose:** "What is going wrong, and what should we fix first?" This page carries the project's key insight.

| Visual | Settings |
|---|---|
| **Two bar charts side by side** (the headline) | Left: `theme_priority[theme]` by `pct_reviews_complaining` titled "How often". Right: same axis by `stars_lost_per_100_reviews` titled "How much it costs the rating". Use the same colour for service and reliability in both |
| Matrix (heatmap) | Rows = brand, Columns = `bridge_review_theme[theme]`, Values = `Complaint Rate`. **Conditional formatting → Background colour → gradient** (white to one dark colour) |
| Line chart | X = `dim_date[year]`, Y = `Complaint Rate`, Legend = theme. Add a brand slicer: pick Norvik and watch service climb |
| Bar chart | `fact_reviews[dealer_region]` by `% Mentions Negative`, with the page filtered to theme = service |
| Text box | One sentence: "Price is the most common complaint, but service and reliability cost the most rating." |

## 5. Page 3: Drill-down & Early Warning

**Purpose:** "Show me the actual reviews" and "what changed this quarter?"

| Visual | Settings |
|---|---|
| Slicers | brand, model, `fact_reviews[model_year]`, `bridge_review_theme[theme]`, `bridge_review_theme[theme_polarity]`, `fact_reviews[sentiment_label]` |
| Table | `date`, brand, model, model_year, rating, `review_text`. Turn on **word wrap**; sort by date descending |
| Table (alerts) | From `alerts.csv`: brand, metric, period, rate, baseline, z. Conditional icon on z |
| Line chart | From `control_chart.csv`, filtered to brand = Velora, metric = reliability. X = period, Y = rate and upper_limit (two lines on the **same** axis) |
| Card | `fact_reviews[mixed_flag]` sum, labelled "Mixed reviews: overall score hides a complaint" |

**Demo script for interviews:** select Velora → Strato → model year 2022 → theme reliability → negative.
The table fills with transmission complaints. Then show the alert table: the problem was flagged in 2022 Q4.

## 6. Design rules (they make the dashboard look professional)

- One accent colour for "the thing that matters"; everything else grey.
- Every page title is a **finding**, not a label: "Service complaints cost the most rating",
  not "Themes page".
- Slicers in one row at the top of every page; use **Sync slicers** (View → Sync slicers) for brand and year.
- Avoid pie charts and 3D visuals; never put two different measures on two y-axes.
- Add a small text box in a corner of every page: "Synthetic data. Illustrates the method."
